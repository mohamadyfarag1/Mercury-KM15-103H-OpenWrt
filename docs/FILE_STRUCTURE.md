# Controller File Structure

This document explains the layout of the `luci-app-horus-controller` source
tree as it actually exists (an earlier revision of this doc described a
Lua/CBI-model LuCI structure — `controller/horus_controller.lua`,
`model/cbi/horus/` — and an entry point `horus-controller.py` that were
never actually used/present; the real UI is JS-based and the real entry
point is `horus-hmp.py`, see below).

The package is built by `build_ipk.py` in the project root, not by the
OpenWrt SDK/buildroot. Run `python3 build_ipk.py` from
`Horus_Controller_Plugin/` to build; it reads the version from `VERSION`,
runs sanity checks (Python/JS syntax, LuCI filename rules — see
`AI_AGENT_RULES.md`), and writes `luci-app-horus-controller_<version>.ipk`
to the same directory.

Only `luci-app-horus-controller/root/` gets shipped inside the package as
`/` on the target device. (An old `build_tmp/` directory sometimes appears
alongside the source tree from manual/ad-hoc build attempts — it is **not**
kept in sync and should not be trusted as a source of truth; treat
`luci-app-horus-controller/root/` as the only real source.)

## `root/etc/`
- **`init.d/horus_controller`**: procd init script. Starts
  `horus-radius.py` (the RADIUS/voucher sync daemon, gated by `enabled`)
  and `horus-hmp.py` (the HMP protocol daemon, gated by
  `role != standalone` or `neighbors_enabled`).
- **`config/horus_controller`**: default UCI config, generated by
  `postinst` with `role='root'` and a **randomly generated per-device**
  `hmp_secret`. Declared as a `conffile`, so opkg preserves the live,
  user-configured version across upgrades instead of overwriting it — this
  is expected behavior, not a bug (see `TROUBLESHOOTING.md`).
- **`uci-defaults/99_horus-controller-patch`**: runs once on install (and
  again explicitly from `postinst` on every reinstall/upgrade). Injects
  `horus_injector.js` + `horus-theme.css` into every native LuCI page's
  `</body>`, and applies the version-based cache-busting rename described
  in `AI_AGENT_RULES.md` rule 4. **Do not hand-edit `PKG_VER` in this
  file — `build_ipk.py` auto-stamps it from `VERSION` on every build.**

## `root/usr/bin/`
- **`horus-hmp.py`**: entry point for the HMP protocol daemon; just calls
  `horus.core.main()`.
- **`horus-radius.py`** / **`horus-radius.sh`**: the RADIUS/voucher sync
  daemon and its wrapper.

## `root/usr/lib/horus/` (the actual daemon code)
- **`core.py`**: reads `role` from UCI and starts the right thread(s) —
  `RootNode` for `role=root` (this is the class that makes this package a
  *controller*; it does not exist in the client project), `SatelliteNode`
  for `role=satellite` or `role=standalone` with neighbor discovery.
- **`root.py`**: the controller logic. Listens for `hello`/`telemetry`,
  maintains `HorusDB`, processes pending UI commands
  (`process_fast_commands()` reads `/tmp/horus_{ban,wifi,ap}_cmd.json`),
  handles anti-spoofing/auto-channel/smart-roaming in `maintenance_loop()`.
  **`fast_cmd_loop()` and `maintenance_loop()` must never both call
  `process_fast_commands()`** — that race condition was a real bug (see
  `CHANGELOG.md`) that could corrupt or double-fire commands.
- **`db.py`**: `HorusDB` — the in-memory + `/tmp/horus_db.json`-persisted
  state store (APs, clients, bans, logs). Also mirrors to
  `/tmp/horus_network_state.json` on every save (the file the frontend
  actually polls).
- **`satellite.py`**: the client-role logic (also used here when this
  package runs in `role=satellite`, e.g. for testing, or `role=standalone`
  for pure P2P discovery). **Must stay byte-identical to the client
  project's copy** except one line (the syslog tag) — see
  `AI_AGENT_RULES.md` rule 1.
- **`protocol.py`**: HMP socket layer (`create_sockets()`,
  `send_hmp_frame()`, `parse_incoming_data()`) — see
  `API_AND_PROTOCOLS.md` for the actual wire format. Must stay
  byte-identical to the client's copy.
- **`config.py`**: constants (`ETH_P_HMP`, `UDP_PORT`, `INTERFACE`, state
  file paths, intervals). Byte-identical to the client's copy.
- **`system.py`**: re-exports everything from `sys_network.py`,
  `sys_wifi.py`, `sys_security.py`, `sys_utils.py` as one import surface.
- **`sys_network.py`**, **`sys_wifi.py`**, **`sys_security.py`**,
  **`sys_utils.py`**: platform glue. All byte-identical to the client's
  copies.
- **`rrm.py`**: background 5GHz scan loop + `get_scan_data()`, used by
  `root.py`'s auto-channel logic. Controller-only (the client instead has
  `rrm_advisor.py` for its own local analysis).
- **`rrm_advisor.py`**, **`rrm_apply.py`**: 5GHz spectrum health analysis
  and the (sanitized, stdin-based — see `CHANGELOG.md`) channel-apply
  backend for `horus_rrm_data` / `horus_rrm_apply`.

There is **no `crypto.py`** — despite what earlier documentation said, no
encryption module exists in this codebase. See `API_AND_PROTOCOLS.md` for
what authentication actually happens (HMAC-SHA256, not encryption).

## `root/www/cgi-bin/`
Plain shell/Python CGI scripts, **not routed through LuCI's session/ACL
system** — they're reachable by anyone on the LAN who can reach the
device's HTTP port, unauthenticated. Be careful adding new ones; see the
command injection fix in `CHANGELOG.md` for what can go wrong here.
`horus_ap_action`, `horus_ban_action`, `horus_groups`, `horus_mac_data`,
`horus_map_data`, `horus_rrm_apply`, `horus_test`, `horus_wifi_action`.

## `root/www/luci-static/resources/` (the actual LuCI UI — JS-based, not Lua/CBI)
- **`horus_controller/i18n.js`**: Arabic/English string dictionary +
  `buildLangBtn()`. Shared module required by `map.js`, `ban.js`,
  `settings.js`, `bulk.js`, `groups.js`, `detail_v2.js`.
- **`horus_controller/styles.js`**: `getStyles()` returns the `<link>` tag
  for `horus-theme.css`, `?v=<version>`-cache-busted.
- **`horus_controller/horus-theme.css`**: the design system — see
  `UI_DESIGN_SYSTEM.md`. **Must stay byte-identical to the client
  project's copy.**
- **`horus_controller/bulk.js`**, **`groups.js`**, **`detail_v2.js`**:
  shared helper modules `require`d only by `map.js` (bulk actions modal,
  AP-groups CBI section builder, the per-AP detail drill-down panel).
- **`view/horus_controller/map.js`**: the dashboard view
  (`admin/services/horus_controller/map`) — live-polled AP table, KPI
  cards, and the "Dashboard" / "AP Groups" internal tabs.
- **`view/horus_controller/ban.js`**: the ban-management view
  (`admin/services/horus_controller/ban`) — banned MAC registry, spoof
  detection log, roam log.
- **`view/horus_controller/settings.js`**: the settings view
  (`admin/services/horus_controller/settings`) — `form.Map`-based CBI
  (role/roaming/radius tabs). See `docs/README.md`/architecture for the
  UCI options.
- **`horus_injector.js`**: injected globally into every native LuCI page
  (see `uci-defaults` above); decorates the stock Network > Wireless >
  Associated Stations table with RADIUS subscriber info and P2P neighbor
  badges. Explicitly no-ops on `horus_controller`'s own pages (it has its
  own native UI already).

**All of `i18n.js`, `styles.js`, `bulk.js`, `groups.js`, `detail_v2.js`,
`map.js`, `ban.js`, and `settings.js` get renamed to `<name>_<version>.js`
on install** by `uci-defaults` for cache-busting — see
`AI_AGENT_RULES.md` rule 4. If you add a new shared module or view,
register it in that script or it won't get this protection.

## `usr/share/luci/menu.d/luci-app-horus-controller.json`
LuCI menu registration for the three views above. Gets rewritten by
`uci-defaults` to point at the version-stamped filenames — don't hand-edit
the `path` fields here expecting them to stick across an install.

## `usr/share/rpcd/acl.d/luci-app-horus-controller.json`
LuCI ACL grants for UCI/file access. Note the `cgi-bin` scripts above don't
actually go through this ACL system at all (see the warning above) — this
file only governs LuCI's own session-based `ubus` calls, which this
project's frontend doesn't currently use for its CGI communication.

## Temporary State Files (Runtime, on the device)
- **`/tmp/horus_db.json`**: `HorusDB`'s own persisted state file.
- **`/tmp/horus_network_state.json`**: mirror of the same state, written on
  every `HorusDB.save()` — this is the file `horus_map_data` actually
  serves to the frontend.
- **`/tmp/horus_ap_peers.json`**: P2P-discovered neighbor APs.
- **`/tmp/horus_{ban,wifi,ap}_cmd.json`**: one-shot command files written
  by the `cgi-bin` action scripts and consumed (then deleted) by
  `RootNode.process_fast_commands()`.
- **`/tmp/horus_radius.json`**: RADIUS/voucher sync daemon output.
